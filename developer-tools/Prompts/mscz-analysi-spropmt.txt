XML STREAM ANALYSIS ARCHITECTURE (BENCHMARK CRITERIA):
We have built a validated Python engine ('motif-concordance.py') that unzips .mscz containers on the fly and parses the underlying .mscx XML file using standard primitive strings (via ET.fromstring) to completely bypass native ElementTree unhashable dict/list pointer conflicts. 

The parsing architecture follows a strict chronological state engine:
1. Linear Timeline Flattening: It processes all nodes sequentially, capturing <StaffText><text> fields for full Hebrew words, <Lyrics><text> fields for English transliteration syllables, and <pitch> values inside <Chord> envelopes.
2. Independent Structural Boundaries: It captures custom agogic phrase breaks (caesuras/atnah pauses patched as <Breath> elements) as distinct, standalone timeline events rather than relying on nested chord properties.
3. Melodic Compression: To isolate underlying motifs (e.g., the E Major Triad 64->68->71), it compresses consecutive duplicate pitch events (e.g., 64->64->68->68->71 collapses to 64->68->71) so syllable changes on the same pitch do not break motif discovery.
4. Hard Caesura Truncation: When a motif match is triggered, text collection runs forward but breaks IMMEDIATELY when the chronological <Breath> milestone is encountered. This prevents textual overflow into post-Atnah clauses and forces clean phrase separation (e.g., Genesis 1a isolated cleanly from 1b).
